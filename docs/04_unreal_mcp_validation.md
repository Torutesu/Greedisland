# Unreal Engine 5.8 / MCP 検証手順

最終更新: 2026-06-21

## 1. 目的

UE5.8の新機能を、ゲーム本体のクリティカルパスに入れる前に検証する。特に Unreal MCP plugin はExperimental扱いのため、最初は開発支援用途として検証し、ランタイムのAI GMとは分離する。

## 2. 検証対象

| 対象 | 目的 | MVPでの扱い |
|---|---|---|
| Unreal MCP plugin | Claude Code等からUEプロジェクトを操作できるか確認 | 開発支援のみ |
| Mesh Terrain | 1ゾーン地形に使えるか確認 | 使えれば採用、詰まれば通常メッシュで代替 |
| MegaLights | 雰囲気作りに使えるか確認 | 余裕があれば採用 |
| MetaHuman Collections | NPCハブ演出に使えるか確認 | MVPでは原則後回し |

## 3. Unreal MCP plugin検証

### 3.1 前提

Epic公式ニュースでは、UE5.8にExperimental MCP pluginが実装され、LLMシステムがエンジンやプロジェクトを理解・操作するための接続口として説明されている。MVPではこれを「開発支援ツール」として扱い、ゲーム内AI GMの実行基盤とは分ける。

### 3.2 Smoke Test

確認項目:

- UE5.8プロジェクトでMCP pluginを有効化できる。
- Claude CodeまたはMCPクライアントから接続できる。
- プロジェクト内のAsset一覧を取得できる。
- Level内Actor一覧を取得できる。
- テスト用FolderまたはAssetを作成できる。
- 変更内容がGit差分またはUEエディタ上で確認できる。

合格条件:

- 接続手順を再現できる。
- 少なくとも読み取り操作が安定する。
- 生成・変更操作が失敗してもプロジェクトを壊さない。

不合格時の対応:

- MCPは使わず、C++とテキストデータ中心の通常開発に戻す。
- BlueprintやLevel操作は手動で行う。
- ランタイムAI GMはバックエンドAPI経由で別途実装する。

## 4. Mesh Terrain検証

### 4.1 目的

浮島、洞窟、オーバーハングなど、通常のハイトマップ地形では表現しづらい島ワールドが作れるかを確認する。

### 4.2 Smoke Test

確認項目:

- 小さな浮島形状を作れる。
- プレイヤーが歩けるCollisionを設定できる。
- イベント地点Actorを配置できる。
- NavMeshまたは簡易移動に問題がない。
- エディタでの編集が重すぎない。

合格条件:

- MVPの1ゾーンをMesh Terrainで作る見通しが立つ。
- 1日以内に最低限の地形が作れる。

不合格時の対応:

- 通常Static MeshまたはLandscapeで1ゾーンを作る。
- Mesh Terrainは次フェーズの世界観強化として再検証する。

## 5. MegaLights検証

### 5.1 目的

カード探索RPGの幻想的な雰囲気を、少数のライト調整で作れるか確認する。

### 5.2 Smoke Test

確認項目:

- 小ゾーンで複数の動的ライトを置ける。
- 戦闘UIやカードUIの視認性を損なわない。
- 60fps目標に大きく影響しない。

合格条件:

- MVPデモの雰囲気改善に使える。

不合格時の対応:

- 標準ライト構成で進める。

## 6. AI GMランタイム検証

MCP pluginとは別に、ゲーム内AI GMはClaude APIをバックエンド経由で呼ぶ。

### 6.1 入力

AIに渡す情報:

- 現在ゾーンID
- イベントID
- NPC ID
- プレイヤーの所持タグ
- 直近の選択肢
- 許可された報酬カードID

AIに渡さない情報:

- APIキー
- 内部デバッグログ全文
- 未公開カード全リスト
- プレイヤーの不要な個人情報

### 6.2 出力

AIから受け取る情報:

- NPCセリフ
- クエスト説明
- 交渉リアクション
- 許可済み報酬候補
- 難易度ヒント

### 6.3 検証

拒否条件:

- JSONとして壊れている。
- 未定義カードIDを含む。
- 許可されていない報酬数を含む。
- 禁止表現を含む。
- IP類似表現を含む。
- 数値範囲を超えている。

## 7. 推奨判断

MVPの最短ルートは以下。

1. C++カード/ルールエンジンを最優先で作る。
2. 地形はMesh Terrainに1日だけ賭け、詰まったら通常メッシュで進める。
3. MCP pluginは開発支援として別枠で検証する。
4. AI GMランタイムはClaude APIをバックエンド経由で実装する。
5. Supabaseはセーブ構造だけ先に合わせ、認証とクラウド保存はMVP後半以降に回す。

# 1ゾーンMVP 実装計画

最終更新: 2026-06-21

## 1. 実装方針

最初の2週間は完成版を目指さず、以下を確認する技術検証とする。

- UE5.8でC++中心のカードルールエンジンを作れるか。
- UMGでカードバトルUIを最低限操作できるか。
- 1ゾーン探索からカード入手、戦闘、報酬、保存まで一周できるか。
- AI GMをゲーム状態から切り離した安全な生成機能として組み込めるか。
- Claude Codeで継続編集しやすい構成にできるか。

## 2. 推奨アーキテクチャ

| レイヤー | 技術 | 方針 |
|---|---|---|
| Core game logic | C++ | カード、ルール、戦闘、探索イベント、保存データ |
| Card data | JSON原本 + UE取込 | Git差分を見やすくし、後でDataTable/DataAssetへ変換 |
| UI | UMG | カード一覧、手札、戦闘ログ、AI会話 |
| World | UE5.8 Mesh Terrainまたは通常メッシュ | MVPでは範囲を小さくし、Experimental依存を抑える |
| AI GM | Backend経由Claude API | クライアントにAPIキーを置かない |
| Save | Local first, Supabase later | セーブ形式はSupabase移行を想定 |
| Dev tooling | Unreal MCP plugin検証 | まず開発支援用途で検証し、ランタイム依存にしない |

## 4. 2週間MVPスケジュール

### Day 1: プロジェクト初期化

成果物:

- UE5.8 C++プロジェクト作成
- Git管理対象の整理
- `docs/` と `data/` の配置
- 最小Map起動
- C++ module構成の確定

タスク:

- `UnrealProject/` を作成する。
- `.gitignore` をUE向けに整える。
- `Cards`, `Rules`, `Combat`, `Exploration`, `AiGm`, `Save` のC++フォルダを用意する。
- 空の1ゾーンマップを作る。

完了条件:

- UEエディタでプロジェクトが開く。
- C++ビルドが通る。
- 空MapでPlayできる。

### Day 2: カードデータ基盤

成果物:

- `FCardDefinition`
- `FCardEffectSpec`
- `FCardConstraintSpec`
- JSONカード定義15枚
- カードロード処理

タスク:

- カード種別、フェーズ、レアリティ、ルールチャンネルをenum化する。
- JSONからカード定義を読み込む。
- 未定義ID、重複ID、未知enumを検出する。
- 開発ログにカード一覧を出す。

完了条件:

- 15枚のカードがロードされる。
- 不正データ時にエラーが出る。

### Day 3: ルールエンジン v0

成果物:

- `URuleResolver`
- 制約チェック
- Rule Patch適用
- 解決ログ

タスク:

- 現在コンテキストを組み立てる。
- 制約を評価する。
- Ruleカードによる例外を適用する。

完了条件:

- 制約を満たさないカードが拒否される。
- Ruleカードにより拒否が許可へ変わる例が動く。
- 解決ログが読める。

### Day 4: 戦闘ループ v0

- 報酬付与の入り口を作る。

完了条件:

- 1体の敵と戦闘し、勝敗が決まる。
- カード使用がルールエンジンを通る。

### Day 5: UMGカードUI
